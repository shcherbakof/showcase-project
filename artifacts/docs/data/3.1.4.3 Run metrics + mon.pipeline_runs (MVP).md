# 3.1.4.3 Run metrics + mon.pipeline_runs (MVP)

Документ фиксирует реализацию подпункта `1.4.3`: сбор счетчиков прогона и запись в `mon.pipeline_runs`.

## Реализация

- Код: [`src/trudvsem/run_metrics.py`](../../../src/trudvsem/run_metrics.py)
- Тесты: [`test/test_run_metrics.py`](../../../test/test_run_metrics.py)

Ключевые сущности:

- `RunMetricsAccumulator` — агрегирует метрики из fetch/write и ошибки.
- `PipelineRunContext` — контекст запуска (`run_id`, `dag_id`, `run_type`, окна).
- `PipelineRunRecord` — финальная запись для `mon.pipeline_runs`.
- `PipelineRunsWriter.write(...)` — upsert в `mon.pipeline_runs`.

## Какие счетчики собираются

- HTTP/fetch: `requests_total`, `requests_success`, `http_429_count`, `http_5xx_count`, `parse_error_count`, `items_extracted`;
- write/raw: `raw_rows_inserted`, `raw_rows_skipped_conflict`, `quarantine_rows`;
- freshness: `max_source_modified_at`, `max_ingested_at`;
- служебные: `timeout_count`, `connection_error_count`, `terminal_http_error_count`.

## Правила статуса run

- `failed`:
  - критическая ошибка (`has_critical_error=True`);
  - или ошибок много и прогресса по данным нет.
- `partial`:
  - есть quarantine;
  - или были HTTP/timeout/parse проблемы;
  - или сработал safety stop.
- `success`:
  - без критических/частичных сигналов.

## error_summary

Формируется автоматически из ключевых ошибок и счетчиков:

- `http_429=...`, `http_5xx=...`, `timeouts=...`, `parse_errors=...`, `quarantine_rows=...`
- плюс до 3 технических сообщений;
- ограничение длины: до 1000 символов.

## Запись в mon.pipeline_runs

- SQL: upsert по `run_id` (`INSERT ... ON CONFLICT DO UPDATE`);
- заполняются все поля минимального контракта из `3.1.3`.

## Пример использования в DAG

```python
from src.trudvsem.run_metrics import PipelineRunContext, PipelineRunsWriter, RunMetricsAccumulator

acc = RunMetricsAccumulator()
acc.add_fetch_diagnostics(fetch_diag)
acc.add_batch_result(write_result)

ctx = PipelineRunContext(
    run_id=run_id,
    dag_id="raw_ingest_vacancies",
    run_type=run_type,
    started_at=started_at,
    window_from=window_from,
    window_to=window_to,
)
record = acc.build_record(context=ctx, has_critical_error=False)
PipelineRunsWriter(conn).write(record)
```
