# 3.1.5.2 Проверка идемпотентности RAW

Документ фиксирует проверку подпункта `1.5.2`: повторный прогон того же окна не размножает версии в `raw.vacancies`.

## Сценарий проверки

1. Сформирован один и тот же тестовый payload вакансии:
- `vacancy_id`: `idem-1ef0c683-26a1-4d75-9010-4975da084a23`
- `source_modified_at_raw`: `2026-02-21T10:00:00+0300`
- окно: `modifiedFrom=2026-02-21T07:00:00Z`, `modifiedTo=2026-02-21T08:00:00Z`

2. Выполнены два последовательных вызова `RawBatchWriter.write_batch(...)` с одинаковыми данными и тем же `run_id`:
- `run_id`: `idem-run-0be24841-b182-4c4d-a935-38a32d459159`

3. Проверен фактический count версий по ключу:
- `(source_system, vacancy_id, source_modified_at_raw)`.

## Результат

- `FIRST_INSERTED = 1`
- `FIRST_SKIPPED = 0`
- `SECOND_INSERTED = 0`
- `SECOND_SKIPPED = 1`
- `TOTAL_VERSIONS = 1`

Вывод: идемпотентность подтверждена, повторный прогон того же окна не размножает версию вакансии.

## Примечание по стенду

В текущем локальном окружении `project_user` не имел прав на `raw.vacancies`, поэтому проверка была выполнена под `postgres` (данные и логика проверки не зависят от пользователя подключения).
