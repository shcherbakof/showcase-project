# 3.1.9.1 Jupyter ручная отладка API -> RAW -> MON

Документ описывает ручной сценарий отладки в Jupyter Notebook для:

1. обращения к API (`fetch_layer`);
2. записи данных в `raw.vacancies` / `raw.quarantine` (`raw_writer`);
3. записи run-метрик в `mon.pipeline_runs` (`run_metrics`).

## 1) Подготовка окружения

В ячейке ноутбука:

```python
import os
import sys
from datetime import datetime, timezone

sys.path.append("/Users/aleksshcherbakov/portfoilo/src")
```

Параметры подключения к БД (локальный стенд):

```python
DB = {
    "host": "localhost",
    "port": 5432,
    "dbname": "project_db",
    "user": "postgres",      # или project_user при корректных правах
    "password": "postgres",  # или project_pass
}
```

## 2) Импорты

```python
import uuid
import psycopg2

from trudvsem.fetch_layer import FetchConfig, SafetyLimits, TrudvsemFetcher
from trudvsem.raw_writer import RawBatchWriter, RawWriteContext
from trudvsem.run_metrics import PipelineRunContext, PipelineRunsWriter, RunMetricsAccumulator
```

## 3) Ручной fetch из API (1 страница для отладки)

```python
fetcher = TrudvsemFetcher(
    FetchConfig(
        limit=20,
        safety=SafetyLimits(max_pages=1, max_items=100),
    )
)

pages = list(
    fetcher.iter_pages(
        modified_from="2026-02-20T00:00:00+00:00",
        modified_to="2026-02-21T23:59:59+00:00",
        region_code="66",  # для отладки можно None или код региона
    )
)

len(pages), fetcher.diagnostics.requests_total, fetcher.diagnostics.requests_success
```

Если API нестабилен и отдает `500`, для отладки writer можно использовать fixture-данные (см. блок 4b).

### 3a) Просмотр содержимого запроса/ответа (контент)

```python
import json

if pages:
    page0 = pages[0]
    print("request_url:", page0.request_url)
    print("request_params:", page0.request_params)
    print("http_status:", page0.http_status)
    print("response_meta:", page0.response_meta)
    print("raw_response_preview:")
    print(json.dumps(page0.raw_response, ensure_ascii=False)[:3000])
else:
    print("Данных нет, см. fetch_error и diagnostics")
```

Примечание: в URL/params `modifiedFrom/modifiedTo` должны уходить в формате UTC `Z` (например `2026-02-20T00:00:00Z`).

## 4) Запись в RAW

### 4a) Запись данных, полученных из API

```python
run_id = f"nb-debug-{uuid.uuid4()}"
conn = psycopg2.connect(**DB)
raw_writer = RawBatchWriter(conn)

acc = RunMetricsAccumulator()
acc.add_fetch_diagnostics(fetcher.diagnostics)

for page in pages:
    ctx = RawWriteContext(
        run_id=run_id,
        endpoint="/api/v1/vacancies",
        request_params=page.request_params,
        http_status=page.http_status,
        request_url=page.request_url,
        response_meta=page.response_meta,
    )
    write_result = raw_writer.write_batch(page.items, ctx)
    acc.add_batch_result(write_result)
```

### 4b) Запись fixture-элемента (если API временно недоступен)

```python
run_id = f"nb-debug-{uuid.uuid4()}"
conn = psycopg2.connect(**DB)
raw_writer = RawBatchWriter(conn)
acc = RunMetricsAccumulator()

item = {
    "id": f"nb-vac-{uuid.uuid4()}",
    "date_modify": "2026-02-21T03:00:00+0300",
    "region": {"region_code": "7700000000000"},
    "name": "Notebook debug vacancy",
}

ctx = RawWriteContext(
    run_id=run_id,
    endpoint="/api/v1/vacancies",
    request_params={"offset": 1, "limit": 1},
    http_status=200,
)

write_result = raw_writer.write_batch([item], ctx)
acc.add_batch_result(write_result)
write_result
```

## 5) Запись run-метрик в mon.pipeline_runs

```python
run_ctx = PipelineRunContext(
    run_id=run_id,
    dag_id="raw_ingest_vacancies",
    run_type="manual",
    started_at=datetime.now(timezone.utc),
    window_from=datetime(2026, 2, 21, 0, 0, tzinfo=timezone.utc),
    window_to=datetime(2026, 2, 21, 1, 0, tzinfo=timezone.utc),
)

record = acc.build_record(
    context=run_ctx,
    has_critical_error=False,
    finished_at=datetime.now(timezone.utc),
)

PipelineRunsWriter(conn).write(record)
record
```

## 6) SQL-проверки результата

```python
with conn.cursor() as cur:
    cur.execute("select count(*) from raw.vacancies where run_id = %s", (run_id,))
    raw_count = cur.fetchone()[0]

    cur.execute("select count(*) from raw.quarantine where run_id = %s", (run_id,))
    quarantine_count = cur.fetchone()[0]

    cur.execute("""
        select status, requests_total, requests_success, items_extracted,
               raw_rows_inserted, raw_rows_skipped_conflict, quarantine_rows
        from mon.pipeline_runs
        where run_id = %s
    """, (run_id,))
    run_row = cur.fetchone()

raw_count, quarantine_count, run_row
```

Ожидаемо:
- `run_row` существует;
- `status` = `success` или `partial` (если quarantine/ошибки);
- `raw_rows_inserted` и `raw_rows_skipped_conflict` согласованы с writer-результатом.

## 8) Частые проблемы при ручной отладке

1. `permission denied for table raw.vacancies`  
- Используй `postgres` в локальном стенде или выдай права `project_user`.

2. `retryable HTTP status=500 exhausted attempts`  
- Источник временно нестабилен; отлаживай writer/metrics на fixture-пейлоаде (блок 4b).

3. `ModuleNotFoundError: trudvsem`  
- Проверь `sys.path.append("/Users/aleksshcherbakov/portfoilo/src")` в ноутбуке.
