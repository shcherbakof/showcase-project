# 5.2.1 Ручные исследования перед реализацией Business Health (MVP)

Документ фиксирует вопросы, которые нужно вручную согласовать до реализации дашборда `Business Health` в рамках блока `5.2` из [`artifacts/docs/data/3. Шаги выполнения checklist.md`](3.%20Шаги%20выполнения%20checklist.md).

Цель: сделать business-дашборд полезным для принятия решений (динамика рынка), а не дублировать технический мониторинг `Pipeline & Data Health`.

## 1) Целевая аудитория и сценарии использования

Вопрос для ручного решения:

- Кто основной пользователь `Business Health`: аналитик, менеджер продукта, руководитель?

Развернутый комментарий:

- Без целевой аудитории нельзя правильно выбрать детализацию и плотность графиков.
- Для менеджмента обычно важнее тренды и отклонения, для аналитика — срезы и drill-down.

Моё мнение:

- MVP-версия должна быть ориентирована на аналитика/менеджера продукта с фокусом на динамику рынка и зарплат.

Мнение пользователя:

- Согласен с тобой
  - MVP-версия должна быть ориентирована на аналитика/менеджера продукта с фокусом на динамику рынка и зарплат

## 2) Горизонт анализа и период по умолчанию

Вопрос для ручного решения:

- Какой период показывать по умолчанию: 14/30/90 дней?

Развернутый комментарий:

- Для бизнес-метрик слишком короткий горизонт даёт шум, слишком длинный — скрывает изменения последних недель.
- Нужен единый стандарт по таймзоне и дате `dt`.

Моё мнение:

- По умолчанию `30 дней`, быстрые переключатели `14` и `90`, таймзона `Europe/Moscow`.

Мнение пользователя:

- Подтверждаю
  - По умолчанию `30 дней`, быстрые переключатели `14` и `90`, таймзона `Europe/Moscow`

## 3) Канонический набор KPI первого экрана

Вопрос для ручного решения:

- Какие KPI считаем обязательными в верхнем блоке карточек?

Развернутый комментарий:

- KPI должны отвечать на вопрос «что происходит с рынком сейчас» за 10-15 секунд.
- Перегрузка карточек снижает ценность дашборда.

Моё мнение:

- Вынести 5 карточек:
  - `active_vacancies_today`,
  - `new_vacancies_today`,
  - `closed_vacancies_today`,
  - `salary_coverage_pct_today`,
  - `median_salary_mid_today`.

Мнение пользователя:

- подтверждаю
  - Вынести 5 карточек:
    - `active_vacancies_today`,
    - `new_vacancies_today`,
    - `closed_vacancies_today`,
    - `salary_coverage_pct_today`,
    - `median_salary_mid_today`.

## 4) Приоритет измерений (dimensions)

Вопрос для ручного решения:

- Какие срезы обязательны в MVP: `region`, `profession`, `employer`?

Развернутый комментарий:

- Набор срезов определяет читаемость и производительность страницы.
- Полный набор сразу может перегрузить и логику, и UI.

Моё мнение:

- MVP: `region` + `profession` как обязательные; `employer` — отдельным блоком топов.

Мнение пользователя:

- Уточняю и потверждаю:
  - MVP: `region` + `profession` как обязательные; `employer` — отдельным блоком топов
  - Для блока `employer`, так же сделать + `region`

## 5) Метрики зарплат

Вопрос для ручного решения:

- Какие зарплатные показатели нужны в первой версии?

Развернутый комментарий:

- Один показатель (например, median) недостаточен для понимания разброса.
- Нужен баланс между информативностью и простотой.

Моё мнение:

- В MVP:
  - `median_salary_mid`,
  - `p25_salary_mid`,
  - `p75_salary_mid`,
  - `% вакансий с указанной зарплатой`.

Мнение пользователя:

- Подтверждаю:
  - В MVP:
    - `median_salary_mid`,
    - `p25_salary_mid`,
    - `p75_salary_mid`,
    - `% вакансий с указанной зарплатой`.

## 6) Метрики динамики вакансий

Вопрос для ручного решения:

- Какие показатели динамики обязательны: активные/новые/закрытые, net change?

Развернутый комментарий:

- Для Business Health важна именно динамика, а не только статические значения.
- Нужен минимум метрик, по которым можно оценить рост/спад рынка.

Моё мнение:

- В MVP использовать:
  - `active_cnt`,
  - `new_cnt`,
  - `closed_cnt`,
  - `net_change = new_cnt - closed_cnt`.

Мнение пользователя:

- Потверждаю:
  - В MVP использовать:
    - `active_cnt`,
    - `new_cnt`,
    - `closed_cnt`,
    - `net_change = new_cnt - closed_cnt`.

## 7) Топы и аутлайеры

Вопрос для ручного решения:

- Какие рейтинги нужны: топ регионов, топ профессий, топ работодателей?

Развернутый комментарий:

- Топы дают быстрый вход в анализ и помогают видеть концентрацию рынка.
- Нужны явные правила сортировки (по объему/по росту).

Моё мнение:

- В MVP:
  - Top-10 регионов по активным вакансиям,
  - Top-10 профессий по активным вакансиям,
  - Top-10 работодателей по активным вакансиям.

Мнение пользователя:

- Потверждаю:
  - В MVP:
    - Top-10 регионов по активным вакансиям,
    - Top-10 профессий по активным вакансиям,
    - Top-10 работодателей по активным вакансиям.
- доп. комментарий по Top-10 регионов:
  - В целом для MVP нормально, не смотря на то, что у нас 3 региона
  - Сделано это специально, так как демонстрационный стенд-портфолио

## 8) Источники данных и единая логика расчета

Вопрос для ручного решения:

- Какие витрины считаем источниками истины для Business Health?

Развернутый комментарий:

- Если смешать источники без контракта, цифры на разных графиках начнут расходиться.
- Нужно заранее определить канонические таблицы и поля.

Моё мнение:

- Базовый источник: `mart.market_daily_kpis`.
- Для employer-блока: `mart.employer_activity`.
- Для детализации/проверок: `mart.vacancy_daily_snapshot`.

Мнение пользователя:

- Потверждаю:
  - Базовый источник: `mart.market_daily_kpis`.
  - Для employer-блока: `mart.employer_activity`.
  - Для детализации/проверок: `mart.vacancy_daily_snapshot`.

## 9) Пороги и сигналы (business anomalies)

Вопрос для ручного решения:

- Нужны ли пороги для бизнес-аномалий на странице (например, резкий спад активных вакансий)?

Развернутый комментарий:

- Даже бизнес-дашборд полезно снабдить простыми сигналами отклонений.
- Но пороги должны быть мягче, чем технические DQ/freshness пороги.

Моё мнение:

- MVP-пороги:
  - `warning`: падение активных вакансий day-over-day > 25%,
  - `error`: падение > 40%.

Мнение пользователя:

- Потверждаю:
  - `warning`: падение активных вакансий day-over-day > 25%,
  - `error`: падение > 40%.

## 10) Минимальная структура страницы Business Health

Вопрос для ручного решения:

- Подтверждаем ли структуру: KPI cards -> dynamics -> salary -> top regions/professions/employers?

Развернутый комментарий:

- Четкий порядок блоков нужен для предсказуемого ежедневного обзора.
- Важно, чтобы пользователь не переключался между разными логиками чтения.

Моё мнение:

- Для MVP сделать 5 секций:
  1. KPI cards,
  2. Dynamics (active/new/closed/net),
  3. Salary trends (median/p25/p75/coverage),
  4. Top regions/professions,
  5. Top employers.

Мнение пользователя:

- Потверждаю
  - Для MVP сделать 5 секций:
    - KPI cards,
    - Dynamics (active/new/closed/net),
    - Salary trends (median/p25/p75/coverage),
    - Top regions/professions,
    - Top employers.
  - Названия возьме русские, ибо бизнес может не знать английский

## 11) Что заполняет пользователь

  - заполнил
- список обязательных KPI первого релиза;
  - заполнил
- подтвержденные источники (`mart.*`) для каждой метрики;
  - потвердил
- пороги бизнес-аномалий (или решение не включать в MVP).
  - потвердил
