# 3.1.4.2 RAW batch write + quarantine (MVP)

Документ фиксирует реализацию подпункта `1.4.2`: батчевая запись в `raw.vacancies` и карантин `raw.quarantine`.

## Реализация

- Код: [`src/trudvsem/raw_writer.py`](../../../src/trudvsem/raw_writer.py)
- Тесты: [`test/test_raw_writer.py`](../../../test/test_raw_writer.py)

Ключевые сущности:

- `RawWriteContext` — общий контекст батча (`run_id`, endpoint, params, status, meta).
- `RawBatchWriter.write_batch(...)` — основная точка записи.
- `BatchWriteResult` — счетчики вставки/конфликтов/quarantine + freshness-поля.

## Что покрыто

1. Вставка в RAW:
- батчевая вставка в `raw.vacancies` через `execute_values`;
- `ON CONFLICT (source_system, vacancy_id, source_modified_at_raw) DO NOTHING`.

2. Валидация минимального контракта:
- `id` -> `vacancy_id`;
- `date_modify` -> `source_modified_at_raw`;
- `region.region_code` -> `region_code_raw`.

3. Quarantine:
- записи с нарушением контракта уходят в `raw.quarantine`;
- типы ошибок: `MISSING_REQUIRED_FIELD`, `INVALID_PAYLOAD_FORMAT`.

4. Технические поля:
- `payload_sha256` для payload;
- `source_modified_at` (parse в UTC, если формат валиден);
- `max_source_modified_at`, `max_ingested_at` в результате батча.

5. Транзакционность:
- успешная запись: `commit`;
- при ошибке: `rollback`.

## Выходные метрики батча

- `raw_rows_inserted`
- `raw_rows_skipped_conflict`
- `quarantine_rows_inserted`
- `max_source_modified_at`
- `max_ingested_at`

## Пример использования в DAG

```python
from src.trudvsem.raw_writer import RawBatchWriter, RawWriteContext

context = RawWriteContext(
    run_id=run_id,
    endpoint=page_endpoint,
    request_params=page.request_params,
    http_status=page.http_status,
    request_url=page.request_url,
    response_meta=page.response_meta,
)

write_result = raw_writer.write_batch(page.items, context)
```
