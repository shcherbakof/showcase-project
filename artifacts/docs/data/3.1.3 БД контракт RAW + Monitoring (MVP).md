# 3.1.3 БД контракт RAW + Monitoring (MVP)

Документ фиксирует утверждённые поля и ключи для блока `1.3`.

## 1) `raw.vacancies` (append-only)

Назначение: журнал версий вакансий, где 1 строка = 1 версия вакансии из источника.

Утверждённые поля:

- `id bigint generated always as identity primary key`
- `run_id text not null`
- `ingested_at timestamptz not null default now()`
- `source_system text not null` (для текущего источника: `trudvsem`)
- `endpoint text not null`
- `request_params jsonb not null`
- `http_status integer not null`
- `payload jsonb not null`
- `vacancy_id text not null` (`payload->>'id'`)
- `source_modified_at_raw text not null` (`payload->>'date_modify'`)
- `source_modified_at timestamptz null` (нормализованная версия `source_modified_at_raw`)
- `region_code_raw text null` (`payload->'region'->>'region_code'`; в текущем ingest отсутствие поля уходит в `raw.quarantine`)
- `response_meta jsonb null`
- `request_url text null`
- `payload_sha256 text null`

Ключ версии для идемпотентности (`ON CONFLICT DO NOTHING`):

- `unique (source_system, vacancy_id, source_modified_at_raw)`

Примечание: если будет подтверждён кейс одинакового `date_modify` при разных payload, усилить ключ до:

- `unique (source_system, vacancy_id, source_modified_at_raw, payload_sha256)`

## 2) `raw.quarantine`

Назначение: хранение записей, не прошедших минимальную валидацию для `raw.vacancies`.

Минимальные поля:

- `id bigint generated always as identity primary key`
- `run_id text not null`
- `ingested_at timestamptz not null default now()`
- `source_system text not null`
- `endpoint text not null`
- `request_params jsonb not null`
- `http_status integer null`
- `payload jsonb null`
- `error_type text not null`
- `error_reason text null`
- `vacancy_id_raw text null`

## 3) `mon.pipeline_runs` (минимальный контракт)

Назначение: data-лог прогона ingest/DAG с операционными метриками.

Утверждённые поля:

- `run_id text primary key`
- `dag_id text not null`
- `run_type text not null default 'scheduled'` (`scheduled|manual|backfill`)
- `status text not null` (`success|partial|failed`)
- `started_at timestamptz not null`
- `finished_at timestamptz null`
- `duration_sec integer null`
- `window_from timestamptz null`
- `window_to timestamptz null`
- `source_system text not null default 'trudvsem'`
- `requests_total integer not null default 0`
- `requests_success integer not null default 0`
- `http_429_count integer not null default 0`
- `http_5xx_count integer not null default 0`
- `parse_error_count integer not null default 0`
- `items_extracted integer not null default 0`
- `raw_rows_inserted integer not null default 0`
- `raw_rows_skipped_conflict integer not null default 0`
- `quarantine_rows integer not null default 0`
- `max_source_modified_at timestamptz null`
- `max_ingested_at timestamptz null`
- `error_summary text null`
- `created_at timestamptz not null default now()`

Индексы:

- `(dag_id, started_at desc)`
- `(status, started_at desc)`

## 4) Правило статусов

- `success`: технических ошибок нет; загрузка завершена; запись в `raw`/`mon` выполнена.
- `partial`: есть частичные ошибки (например, quarantine > 0 или часть страниц не обработана), но прогресс есть.
- `failed`: прогресса по данным нет или критическая ошибка (auth/schema/фатальные retry exhaustion).
