# 3.1.10.3 Master-DAG + Watermark: реализация и валидация

Дата: 2026-02-22

## Что реализовано (порядок 2 -> 1 -> 3 -> 4)

### 2) Watermark-контур (обязательно)

- Добавлена миграция: [`sql/db/project/migrations/002_watermarks_master_regions.sql`](../../../sql/db/project/migrations/002_watermarks_master_regions.sql)
  - Создана таблица `mon.watermarks`.
  - Добавлены bootstrap-записи для регионов `66`, `77`, `78`.
- Миграция применена через `make init-db`.

### 1) Master DAG (последовательный запуск, без параллели)

- Добавлен DAG: [`airflow/dags/raw_master_regions_dag.py`](../../../airflow/dags/raw_master_regions_dag.py)
- Логика:
  - последовательно запускает child-run для `66 -> 77 -> 78`;
  - ожидает завершения каждого child-run (`wait_for_completion=True`);
  - `max_active_runs=1`;
  - пауза между регионами настраивается (`pause_between_regions_sec`).

### 3) Оркестрация child DAG + обновление watermark

- Child DAG: `raw_ingest_vacancies`.
- Для каждого региона master:
  - формирует окно из `mon.watermarks` (`window_from`) и `now - safety_lag` (`window_to`),
  - триггерит child-run с `conf`,
  - после `success` обновляет `mon.watermarks`.
- Обновление watermark выполняется только при успешном завершении соответствующего региона.

### 4) Валидация

- Успешный мастер-run:
  - `raw_master_regions / manual_20260222_master_v1` -> `success`.
- Успешные child-run:
  - `manual_20260222_master_v1__region_66` -> `success`
  - `manual_20260222_master_v1__region_77` -> `success`
  - `manual_20260222_master_v1__region_78` -> `success`
