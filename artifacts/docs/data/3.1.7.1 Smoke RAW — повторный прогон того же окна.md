# 3.1.7.1 Smoke RAW — повторный прогон того же окна

Документ фиксирует проверку подпункта `1.6.2`: при повторном прогоне того же окна растет `raw_rows_skipped_conflict`, при этом дубли версий в `raw.vacancies` не появляются.

## Сценарий проверки

Выполнены два последовательных локальных fixture-прогона с одинаковыми:

- окном:
  - `WINDOW_FROM = 2026-02-21T00:00:00+00:00`
  - `WINDOW_TO = 2026-02-21T00:10:00+00:00`
- payload вакансии:
  - `VACANCY_ID = smoke-repeat-vac-ae592e3b-ce9d-43f5-b712-3d3edab53d3f`
  - `source_modified_at_raw = 2026-02-21T03:00:00+0300`

Прогоны:

- `RUN1_ID = smoke-repeat-1-a6116afe-c86e-4efa-a147-001048cb577b`
- `RUN2_ID = smoke-repeat-2-0047bf88-8d80-46a5-952c-395c8b01d440`

## Результаты

- Run1:
  - `RUN1_INSERTED = 1`
  - `RUN1_SKIPPED = 0`
  - `RUN1_STATUS = success`
- Run2 (то же окно и та же версия):
  - `RUN2_INSERTED = 0`
  - `RUN2_SKIPPED = 1`
  - `RUN2_STATUS = success`
- Проверка дублей по ключу версии:
  - `VERSIONS_COUNT = 1`

## Вывод

Критерий `1.6.2` подтвержден:

- `raw_rows_skipped_conflict` во втором прогоне вырос;
- дублей “версий” нет (`VERSIONS_COUNT = 1`).

## Дополнительно: live fetch API (region=66, 1 страница)

Проверка выполнена `2026-02-21` через `TrudvsemFetcher` с `max_pages=1`:

- `window_from = 2026-02-20T15:56:30+00:00`
- `window_to = 2026-02-21T15:56:30+00:00`
- `region_code = 66`
- `limit = 20`

Факт по параметрам запроса:

- в fetch-layer переданы исправленные значения времени в формате UTC `Z`:
  - `modifiedFrom = 2026-02-20T15:56:30Z`
  - `modifiedTo = 2026-02-21T15:56:30Z`
- endpoint: `/api/v1/vacancies/region/66`

Факт по ответу источника:

- `status = error`
- `error = connection error after 5 attempts`
- `requests_total = 5`
- `requests_success = 0`
- `pages_fetched = 0`
- `items_extracted = 0`

Вывод: формат URL/параметров исправлен и применяется, но в момент проверки источник не вернул страницу данных из-за сетевой ошибки подключения.
