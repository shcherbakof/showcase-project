# 3.3.3 Правила консистентности MARTS (MVP)

Документ фиксирует реализацию подпункта `3.3` из верхнеуровневого чек-листа.

## 1) Явное определение дня `dt` и таймзоны

Принято и реализовано:

- бизнес-день `dt` считается в таймзоне `Europe/Moscow`;
- во всех refresh-функциях MART используется приведение timestamp -> local date через `AT TIME ZONE 'Europe/Moscow'`;
- в агрегатных таблицах MART (`mart.market_daily_kpis`, `mart.employer_activity`) хранится поле `timezone_name` со значением `Europe/Moscow`.

Техническая фиксация в БД:

- добавлены check-ограничения:
  - `chk_mart_market_daily_kpis_timezone_moscow`
  - `chk_mart_employer_activity_timezone_moscow`
- миграция: [`sql/db/project/migrations/009_marts_consistency_rules_mvp.sql`](../../../sql/db/project/migrations/009_marts_consistency_rules_mvp.sql)

## 2) Атомарность обновления MARTS

Реализован единый entrypoint обновления:

- `mart.refresh_all_vitrines(p_date_from, p_date_to)`

Гарантии консистентности:

1. Один вызов функции = одна SQL-транзакция (стандартное поведение PostgreSQL для statement-вызова функции).
2. Добавлен transaction-scoped lock:
   - `pg_advisory_xact_lock(hashtext('mart.refresh_all_vitrines'))`
   - исключает параллельные refresh-конфликты.
3. Порядок обновления фиксирован:
   - snapshot -> market -> employer.
4. При ошибке на любом шаге транзакция откатывается целиком (частично обновлённые MART-таблицы не остаются).

## 3) Что считается выполненным по чек-листу 3.3

- Пункт "Явно определить день (`dt`) и таймзону" — выполнен.
- Пункт "Атомарность обновления marts" — выполнен.

## 4) Быстрая проверка

```sql
select * from mart.refresh_all_vitrines('2026-02-22'::date, '2026-02-22'::date);

select distinct timezone_name from mart.market_daily_kpis;
select distinct timezone_name from mart.employer_activity;
```
