## Найти и зафиксировать в payload

- [ ] `vacancy_id` (как называется и где лежит)
  - пример id вакансии: {"results": {"vacancies": [{"vacancy": {"id": "4cfe31f0-0e3c-11f1-a990-837b73ca4e2b"}}]}}
    - id вакансии называется id
- [ ] поле “версионности” (`source_modified_at`) — **что гарантированно меняется при изменениях**
  - [ ] пример поля версионности: {"results": {"vacancies": [{"vacancy": {"date_modify": "2026-02-20T13:34:06+0300",}}]}}
    - имя поля версионности: date_modify
  - пример поля создания: {"results": {"vacancies": [{"vacancy": {"creation-date": "2026-02-20"}}]}}
    - имя поля создания: creation-date
- [ ] (опционально) поля, которые помогут для freshness/фильтра (регион, статус)
  - регион
    - {"results": {"vacancies": [{"vacancy": {"region": {"region_code": "6600000000000",}}}]}}
    - имя поля region_code
    - коды регионов состоят из двух или трех значного числа. В ответе дописываются нолями
  - статус
    - таких значений в ответе нет

## Принять решение по `source_modified_at`

используем поле date_modify
