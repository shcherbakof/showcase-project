# 5.1.2 Подготовка UI сборки дашборда Data Health (MVP)

Документ фиксирует реализацию UI-сборки дашборда Superset для пункта `5.2` из [`artifacts/docs/data/3. Шаги выполнения checklist.md`](3.%20Шаги%20выполнения%20checklist.md).

## 1) Что реализовано

1. Добавлен idempotent-скрипт сборки charts + dashboard:

- [`superset/assets/build_pipeline_health_dashboard.py`](../../../superset/assets/build_pipeline_health_dashboard.py)

2. Подключен автозапуск сборки в Superset bootstrap:

- [`superset/bootstrap.sh`](../../../superset/bootstrap.sh)

3. Сборка выполняется после импорта datasets (`datasources.yaml`) и формирует:

- Dashboard: `Pipeline & Data Health (MVP)` (`slug=pipeline-data-health-mvp`)
- 6 charts:
  - `[MVP] Status Cards`
  - `[MVP] Freshness Snapshot`
  - `[MVP] Volumes Daily`
  - `[MVP] DQ Daily`
  - `[MVP] DQ Current`
  - `[MVP] Last Runs`

## 2) Технический подход

- Подход: программный upsert через Superset ORM в `app_context`.
- Идемпотентность:
  - повторный запуск не создает дубликаты dashboard/charts;
  - существующие объекты обновляются по `dashboard_title` и `slice_name`.
- Перед созданием/обновлением chart выполняется `dataset.fetch_metadata()`:
  - это синхронизирует колонки datasets из БД,
  - устраняет ошибки вида `Columns missing in dataset`.
- Layout:
  - формируется `position_json` в grid-структуре (2 charts в строке).

## 3) Проверка в окружении

Выполнено:

1. `make up-superset` (init + run) — успешно.
2. Контроль metadata:

- `dashboard slug=pipeline-data-health-mvp` найден, `published=true`;
- `slices_count=6`.

3. Контроль идемпотентности:

- повторный запуск `python /app/project/superset/assets/build_pipeline_health_dashboard.py`;
- после повтора: `dashboards=1`, `mvp_slices=6`.
