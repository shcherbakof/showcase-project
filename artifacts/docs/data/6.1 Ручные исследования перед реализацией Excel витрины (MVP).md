# 6.1 Ручные исследования перед реализацией Excel витрины (MVP)

Документ фиксирует вопросы, которые нужно вручную согласовать до реализации блока `6` из [`artifacts/docs/data/3. Шаги выполнения checklist.md`](3.%20Шаги%20выполнения%20checklist.md).

Цель: сделать ежедневный Excel-отчёт полезным бизнесу и воспроизводимым в автоматическом пайплайне, без ручной сборки.

## 1) Целевая аудитория и сценарий чтения

Вопрос для ручного решения:

- Кто основной читатель файла: менеджер, аналитик, руководитель?

Развернутый комментарий:

- От роли зависит глубина отчёта: менеджеру нужны короткие KPI и топы, аналитику — больше деталей и диагностик.

Моё мнение:

- MVP ориентировать на менеджера/руководителя как ежедневный обзор, с минимально достаточной аналитической детализацией.

Мнение пользователя:

- Поддерживаю:
  - MVP ориентировать на менеджера/руководителя как ежедневный обзор, с минимально достаточной аналитической детализацией.

## 2) Период отчёта и таймзона

Вопрос для ручного решения:

- Какой период должен быть в ежедневном файле: только вчерашний день, скользящее окно 7/30 дней, или оба варианта?

Развернутый комментарий:

- В daily-процессе важно не смешивать оперативный срез и тренд без явных правил.

Моё мнение:

- В `Summary` показывать текущий день `dt` + day-over-day;
- в отдельных листах топов — `dt` + тренд за последние 30 дней;
- таймзона: `Europe/Moscow`.

Мнение пользователя:

- Поддерживаю
  - В `Summary` показывать текущий день `dt` + day-over-day;
  - в отдельных листах топов — `dt` + тренд за последние 30 дней;
  - таймзона: `Europe/Moscow`.

## 3) Канонический набор листов

Вопрос для ручного решения:

- Подтверждаем ли структуру файла: `Summary`, `Top regions`, `Top professions`, `Top employers`, `Exceptions`?

Развернутый комментарий:

- Фиксированная структура нужна для предсказуемости ежедневного чтения и автоматической проверки содержимого.

Моё мнение:

- Подтвердить 5 листов как обязательные для MVP.

Мнение пользователя:

- Сделай названия вкладов на русском языке
- Структуру подтверждаю
- Легенду сделать отдельным титульным листом с информацией по всем вкладкам

## 4) KPI для листа Summary

Вопрос для ручного решения:

- Какие KPI обязательно должны быть на первом листе?

Развернутый комментарий:

- KPI должны совпадать с логикой Business Health, чтобы Superset и Excel показывали согласованные цифры.

Моё мнение:

- Вынести: `active`, `new`, `closed`, `net_change`, `salary_coverage_pct`, `median_salary_mid`, `p25`, `p75`, `active_change_pct_dod`.

Мнение пользователя:

- Потверждаю:
  - Вынести: `active`, `new`, `closed`, `net_change`, `salary_coverage_pct`, `median_salary_mid`, `p25`, `p75`, `active_change_pct_dod`.
  - Сделать названия на русском языке

## 5) Правила Top-листов

Вопрос для ручного решения:

- Какие правила сортировки и размер Top использовать?

Развернутый комментарий:

- Без явных правил Top-листы будут "прыгать" и затруднят сравнение между днями.

Моё мнение:

- MVP:
  - `Top regions`: Top-10 по `active_vacancies`;
  - `Top professions`: Top-10 по `active_vacancies`;
  - `Top employers`: Top-10 по `active_vacancies` с колонкой `region`;
  - tie-break: по наименованию по возрастанию.

Мнение пользователя:

- Потверждаю твое мнение
  - `Top regions`: Top-10 по `active_vacancies`;
  - `Top professions`: Top-10 по `active_vacancies`;
  - `Top employers`: Top-10 по `active_vacancies` с колонкой `region`;
  - tie-break: по наименованию по возрастанию.

## 6) Секция Exceptions

Вопрос для ручного решения:

- Что считаем исключениями в Excel-отчёте?

Развернутый комментарий:

- Нужен минимальный список сигналов, чтобы файл был не только "витриной", но и индикатором риска данных.

Моё мнение:

- В MVP в `Exceptions` выводить:
  - `active_drop_severity` (`warning/error`),
  - резкие просадки по ключевым KPI,
  - технический флаг пустого отчёта.

Мнение пользователя:

- Подтверждаю
  - В MVP в `Exceptions` выводить:
    - `active_drop_severity` (`warning/error`),
    - резкие просадки по ключевым KPI,
    - технический флаг пустого отчёта.

## 7) Источники данных (single source of truth)

Вопрос для ручного решения:

- Какие таблицы/вью считаем источником истины для Excel?

Развернутый комментарий:

- Нужно исключить расхождение с дашбордом Business Health.

Моё мнение:

- База: `mart.market_daily_kpis`, `mart.employer_activity`, `mart.vacancy_daily_snapshot`;
- при необходимости использовать `mon.v_business_health_*` как слой готовых вычислений.

Мнение пользователя:

- Потверждаю
  - База: `mart.market_daily_kpis`, `mart.employer_activity`, `mart.vacancy_daily_snapshot`;
  - при необходимости использовать `mon.v_business_health_*` как слой готовых вычислений.
    - Понять что есть необходимость - твои предложения?
- Подтверждаю вариант B:
  - `mon.v_business_health_*` для `Summary/Exceptions`,
  - `mart.*` для top-листов и детализации.

## 8) Именование файла и каталог

Вопрос для ручного решения:

- Какой шаблон имени и путь хранения файла утверждаем?

Развернутый комментарий:

- Единый шаблон нужен для автоматической выгрузки/архива и проверки наличия файла за день.

Моё мнение:

- Путь: `artifacts/reports/excel/`;
- имя: `business_health_YYYY-MM-DD.xlsx`;
- опционально добавлять `run_id` в метаданные (не в имя).

Мнение пользователя:

- Потверждаю:
  - Путь: `artifacts/reports/excel/`;
  - имя: использовать системную дату/время формирования файла;
  - опционально добавлять `run_id` в метаданные (не в имя)

## 9) Правило "пустого отчёта"

Вопрос для ручного решения:

- Что делать, если данных за `dt` нет: не создавать файл, создавать пустой файл, или создавать файл с явным статусом?

Развернутый комментарий:

- Самый опасный вариант — "тихий" пустой файл без явной индикации.

Моё мнение:

- Всегда создавать файл, но на `Summary` показывать `status=no_data` и причины (какой источник пустой).

Мнение пользователя:

- Потверждаю
  - Всегда создавать файл, но на `Summary` показывать `status=no_data` и причины (какой источник пустой).
  - Причину пишем на русском языке
