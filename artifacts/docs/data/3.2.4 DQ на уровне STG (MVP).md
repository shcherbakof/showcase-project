# 3.2.4 DQ на уровне STG (MVP)

Документ фиксирует реализацию подпункта `2.4` из верхнеуровневого чек-листа.

## 1) Ключи и обязательность полей

Для `stg.vacancies` зафиксировано:

- `vacancy_id` — `PRIMARY KEY` (=> `UNIQUE` + `NOT NULL`);
- `employer_key` — `NOT NULL`;
- `source_modified_at` — `NOT NULL`.

Примечание по `employer_key`: уникальность **не** вводится, так как один работодатель может иметь много вакансий.

## 2) Диапазоны зарплат

На уровне таблицы включены проверки:

- `salary_from >= 0` (если задано),
- `salary_to >= 0` (если задано),
- `salary_from <= salary_to` (если заданы обе границы).

Эти ограничения уже реализованы в [`sql/db/project/migrations/005_stg_transform_rules_mvp.sql`](../../../sql/db/project/migrations/005_stg_transform_rules_mvp.sql).

## 3) `modified_at` не null и не «в будущем» (с допуском)

Для поля версии STG (`source_modified_at`) действует:

- `NOT NULL`;
- добавлен check с допуском +1 день:
  - `source_modified_at <= now() + interval '1 day'`.

Реализация: [`sql/db/project/migrations/007_stg_dq_mvp.sql`](../../../sql/db/project/migrations/007_stg_dq_mvp.sql).

## 4) Операционный DQ-срез

Добавлено представление:

- `mon.v_stg_vacancies_dq`

Показывает агрегированные DQ-счётчики:

- null/empty ключи,
- некорректные зарплаты,
- `source_modified_at` null/future,
- невалидные `status_norm`.

Пример проверки:

```sql
select * from mon.v_stg_vacancies_dq;
```

## 5) Результат для чек-листа 2.4

- Пункт про `NOT NULL/UNIQUE` ключей закрыт.
- Пункт про диапазоны зарплат закрыт.
- Пункт про `modified_at` с допуском закрыт.
