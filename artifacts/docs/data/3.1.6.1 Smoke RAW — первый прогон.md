# 3.1.6.1 Smoke RAW — первый прогон

Документ фиксирует проверку подпункта `1.6.1`: первый прогон создает строки в `raw.vacancies` и запись в `mon.pipeline_runs` с тем же `run_id`.

## Результат проверки (выполнено)

Проверка выполнена локальным fixture-прогоном через `RawBatchWriter` + `PipelineRunsWriter`:

- `RUN_ID = smoke-local-1c013aab-6b65-406a-8ba4-50881449d072`
- `RAW_COUNT = 1` (в `raw.vacancies`)
- `MON_COUNT = 1` (в `mon.pipeline_runs`)
- `STATUS = success`
- `RAW_INSERTED = 1`
- `RAW_SKIPPED = 0`
- `QUARANTINE = 0`

Вывод: критерий `1.6.1` подтвержден, `run_id` совпадает в `raw.*` и `mon.*`.

## Примечание по внешнему API

E2E-прогон через реальный fetch на текущем стенде возвращал стабильный `HTTP 500` от источника (`opendata.trudvsem.ru`) для tested window, поэтому для smoke-подтверждения использован контролируемый локальный прогон с валидным fixture.
