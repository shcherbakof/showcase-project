# 5.1.3 Руководство по дашборду Pipeline & Data Health (MVP)

Документ описывает, как читать и использовать дашборд `Pipeline & Data Health (MVP)` в Superset.

Связанные документы:

- [`artifacts/docs/data/5.1 Мониторинг Superset Pipeline & Data Health (MVP).md`](5.1%20Мониторинг%20Superset%20Pipeline%20&%20Data%20Health%20(MVP).md)
- [`artifacts/docs/data/5.1.2 подготовка UI сборка дашборда Data Health (MVP).md`](5.1.2%20подготовка%20UI%20сборка%20дашборда%20Data%20Health%20(MVP).md)

## 1) Назначение

Дашборд отвечает на 3 операционных вопроса:

1. Жив ли конвейер (последний run и freshness).
2. Не пропали ли объёмы данных между слоями RAW/STG/MART.
3. Нет ли критичных DQ-проблем, влияющих на доверие к данным.

## 2) Состав дашборда

Дашборд содержит 6 виджетов:

1. `[MVP] Status Cards` — итоговые KPI текущего состояния.
2. `[MVP] Freshness Snapshot` — свежесть данных и статус последнего run.
3. `[MVP] Volumes Daily` — дневные объёмы и day-over-day отклонения.
4. `[MVP] DQ Daily` — дневные DQ-метрики.
5. `[MVP] DQ Current` — текущие DQ-сигналы.
6. `[MVP] Last Runs` — журнал последних запусков.

## 3) Как интерпретировать ключевые поля

`latest_run_status`:

- `success` — run завершён без критики и warning-gate.
- `partial` — run завершён, но есть предупреждения DQ.
- `failed` — run с критической ошибкой.

`quality_label`:

- `ok` / `warning` / `failed` — нормализованный индикатор качества последнего run.

`freshness_delay_min`:

- задержка в минутах между `now()` и `max(raw.vacancies.ingested_at)`.

`raw_rows_today`, `stg_rows_today`, `mart_rows_today`:

- суточные объёмы по слоям в таймзоне `Europe/Moscow`.

`dq_warning_count`, `dq_error_count`:

- агрегированные счётчики предупреждений/ошибок по freshness, volumes и DQ.

## 4) Пороги warning/error (MVP)

Freshness:

- `warning`: `freshness_delay_min > 360` (6 часов)
- `error`: `freshness_delay_min > 720` (12 часов)

Volumes day-over-day:

- `warning`: падение `<= -40%`
- `error`: падение `<= -70%`

DQ `%UNKNOWN`:

- `warning`: `> 20%`
- `error`: `> 40%`

Дополнительно `error`:

- `critical_emptiness = true`
- `source_modified_at_future_rows > 0`

## 5) Базовый порядок daily-проверки

1. Открыть `Status Cards` и проверить `latest_run_status`, `quality_label`, `freshness_delay_min`.
2. Если есть `dq_error_count > 0`, перейти в `DQ Current` и `Last Runs`.
3. Проверить `Volumes Daily` на резкие просадки day-over-day.
4. Для инцидента зафиксировать `run_id` из `Last Runs` и разбирать первопричину в пайплайне.

## 6) Типовые инциденты и действия

`Columns missing in dataset`:

- причина: рассинхрон metadata колонок в Superset;
- действие: выполнить `make up-superset` (bootstrap вызовет sync через `dataset.fetch_metadata()`).

`freshness_severity = error`:

- проверить наличие новых run в `Last Runs`;
- проверить RAW-инжест и источник данных.

`резкое падение объёмов`:

- сверить `raw_rows_today` vs `stg_rows_today` vs `mart_rows_today`;
- проверить DQ-блок и свежесть.
