# 3.1.10.4 Как запускать DAG-и и что проверять после запуска

## Предусловия

- Airflow поднят: `make up-airflow`
- UI доступен: `http://localhost:8080`
- Пользователь: `admin` / `admin` (если не менялся)

## Основной сценарий: запуск master DAG

DAG: `raw_master_regions`

### Запуск через UI

1. Открыть `http://localhost:8080`.
2. Найти DAG `raw_master_regions`.
3. Убедиться, что DAG не на паузе (`Unpause`, если нужно).
4. Нажать `Trigger DAG`.
5. Выбрав Trigger DAG w/ config опционально передать `conf`:

```json
{
  "limit": 100,
  "max_pages": 500,
  "max_items": 50000,
  "pause_between_regions_sec": 60,
  "safety_lag_sec": 300
}
```

### Запуск через CLI

```bash
docker compose -f compose.yml --env-file .env exec -T airflow-webserver \
  airflow dags trigger raw_master_regions \
  -r manual_YYYYMMDD_master_v1 \
  -c '{"limit":100,"max_pages":500,"max_items":50000,"pause_between_regions_sec":60,"safety_lag_sec":300}'
```

## Что делает master DAG

- Последовательно запускает child ingestion:
  - регион `66`
  - регион `77`
  - регион `78`
- Для каждого региона:
  - читает watermark из `mon.watermarks`,
  - формирует окно,
  - запускает `raw_ingest_vacancies`,
  - обновляет watermark только при `success`.

## Что проверять после запуска

### 1) Статус master run

```bash
docker compose -f compose.yml --env-file .env exec -T airflow-webserver \
  airflow dags list-runs -d raw_master_regions --no-backfill
```

Ожидание: нужный `run_id` в `success`.

### 2) Статусы child run по регионам

```bash
docker compose -f compose.yml --env-file .env exec -T airflow-webserver \
  airflow dags list-runs -d raw_ingest_vacancies --no-backfill
```

Проверить `run_id` вида `<master_run_id>__region_66/77/78`.
Ожидание: три `success`.

### 3) Результаты в `mon.pipeline_runs`

```bash
docker compose -f compose.yml --env-file .env exec -T postgres \
  psql -U postgres -d project_db \
  -c "select run_id, status, window_from, window_to, requests_total, requests_success, raw_rows_inserted, error_summary from mon.pipeline_runs where run_id like '<master_run_id>__region_%' order by run_id;"
```

### 4) Обновление watermark

```bash
docker compose -f compose.yml --env-file .env exec -T postgres \
  psql -U postgres -d project_db \
  -c "select region_code, watermark_value, updated_by_run_id, updated_at from mon.watermarks where source_system='trudvsem' and entity_name='vacancies' order by region_code;"
```

Ожидание: `updated_by_run_id` указывает на успешные child run.

### 5) Аудит watermark (append-only)

```bash
docker compose -f compose.yml --env-file .env exec -T postgres \
  psql -U postgres -d project_db \
  -c "select id, region_code, old_watermark_value, new_watermark_value, changed_by_run_id, change_source, changed_at from mon.watermark_history order by id desc limit 20;"
```

Ожидание: новые записи аудита после изменений watermark.

## Ручной запуск только одного региона (child DAG)

Если нужен точечный запуск по региону (без master):

```bash
docker compose -f compose.yml --env-file .env exec -T airflow-webserver \
  airflow dags trigger raw_ingest_vacancies \
  -r manual_YYYYMMDD_66_v1 \
  -c '{"window_from":"2025-01-01T00:00:00+00:00","window_to":"2025-01-01T00:00:00+00:00","region_code":"66","limit":100,"max_pages":500,"max_items":50000}'
```

## Типовые проблемы

- `queued` долго не стартует:
  - проверить, нет ли уже `running` run этого DAG при `max_active_runs=1`.
- `permission denied` в `raw.*`/`mon.*`:
  - выполнить `make init-db` (применяются grant-скрипты).
- `DagNotFound`:
  - подождать, либо перезапустить Airflow `make up-airflow`.
