# 4.2 Оркестрация Airflow end-to-end (MVP)

Документ фиксирует реализацию блока `4` из [`artifacts/docs/data/3. Шаги выполнения checklist.md`](3.%20Шаги%20выполнения%20checklist.md) на основе согласований из [`artifacts/docs/data/4.1 Ручные исследования перед реализацией Оркестрации Airflow (end-to-end).md`](4.1%20Ручные%20исследования%20перед%20реализацией%20Оркестрации%20Airflow%20(end-to-end).md).

## 1) Архитектура DAG (2 уровня)

Реализована двухуровневая схема:

1. `raw_master_regions` — RAW-контур (66 -> 77 -> 78 + watermark).
2. `stg_marts_pipeline` — downstream-контур (`STG -> MARTS -> DQ -> quality marker -> run stats`).

Связь между DAG:

- в конце `raw_master_regions` добавлен `TriggerDagRunOperator` на `stg_marts_pipeline` с передачей `source_run_id/source_dag_id/raw_window_from/raw_window_to` через `conf`.

## 2) Расписание и очередь запусков

Зафиксировано расписание в `Europe/Moscow`:

- два слота в сутки: `07:00` и `16:00`.

Реализовано:

- `raw_master_regions`: `schedule="0 7,16 * * *"`, `max_active_runs=1`;
- `stg_marts_pipeline`: `schedule="0 7,16 * * *"`, `max_active_runs=1`.

Поведение при пересечении запусков:

- новые run ставятся в очередь (за счёт `max_active_runs=1`).

## 3) Retry/timeout политика

### DAG-level (`stg_marts_pipeline`)

- `retries=2`
- `retry_delay=10m`
- `dagrun_timeout=90m`

### Тяжёлые задачи

- `refresh_marts`: `retries=1`, `execution_timeout=45m`

### Лёгкие проверки

- `run_quality_checks`: `retries=1`, `execution_timeout=10m`
- `emit_report_quality_marker`: `retries=1`, `execution_timeout=10m`

## 4) Правила `partial` / `failed`

В `stg_marts_pipeline` реализовано единообразное правило записи в `mon.pipeline_runs`:

- `failed`:
  - есть critical-ошибка слоя,
  - или upstream task failed/upstream_failed.
- `partial`:
  - слой построен,
  - есть warning по DQ,
  - quality marker = `warning`.
- `success`:
  - критичных ошибок нет,
  - warning нет.

Реализовано в task `write_run_stats` DAG `stg_marts_pipeline`.

## 5) DQ gate и выпуск quality-marker

Применена policy `warning-gate`:

- critical DQ (пустые snapshot/market/employer) -> `failed`;
- warning DQ (например низкая salary coverage / UNKNOWN buckets) -> `partial`.

Выпуск файла с меткой качества реализован task `emit_report_quality_marker`:

- путь: `artifacts/reports/excel_quality/<run_id>.json`
- внутри: `quality_label`, warnings/critical, объёмы витрин, source run metadata.

## 8) Проверка запуска (пример)

1. Запустить `raw_master_regions` (manual/scheduled).
2. Убедиться, что после региона `78` автоматически запущен `stg_marts_pipeline`.
3. Проверить `mon.pipeline_runs` для `stg_marts_pipeline`.
4. Проверить наличие quality-marker в `artifacts/reports/excel_quality/`.
