# 3.1.4.1 Fetch-layer (MVP)

Документ фиксирует реализацию подпункта `1.4.1`: paging + retry/backoff+jitter + safety stop + диагностика.

## Реализация

- Код: [`src/trudvsem/fetch_layer.py`](../../../src/trudvsem/fetch_layer.py)
- Тесты: [`test/test_fetch_layer.py`](../../../test/test_fetch_layer.py)

Ключевые сущности:

- `FetchConfig` — базовый URL/endpoint, paging, retry, safety.
- `RetryConfig` — `max_attempts`, `base_delay_sec`, `max_delay_sec`, `jitter_sec`, `timeout_sec`.
- `SafetyLimits` — `max_pages`, `max_items`.
- `FetchDiagnostics` — операционные счетчики и события.
- `TrudvsemFetcher.iter_pages(...)` — поток страниц API.

## Что покрыто

1. Paging:
- `offset/limit` с шагом `limit` (или `offset_step`, если задан).
- остановка на пустой странице (`empty_page`) или короткой странице (`short_page`).

2. Retry policy:
- retry для `429`, `500`, `502`, `503`, `504`;
- retry для `requests.Timeout` и `requests.ConnectionError`;
- exponential backoff + jitter перед повтором.

3. Safety stop:
- остановка по `max_pages_reached`;
- остановка по `max_items_reached`.

4. Диагностика:
- `requests_total`, `requests_success`;
- `http_429_count`, `http_5xx_count`;
- `timeout_count`, `connection_error_count`, `parse_error_count`;
- `items_extracted`, `events`, `stopped_reason`.

## Ограничения (MVP)

- Пока без async/параллельной загрузки.
- Политика завершения paging основана на длине страницы и safety-лимитах.

## Пример использования в DAG

```python
from src.trudvsem.fetch_layer import FetchConfig, TrudvsemFetcher

fetcher = TrudvsemFetcher(FetchConfig(limit=100))
for page in fetcher.iter_pages(modified_from=window_from, modified_to=window_to):
    handle_page(page)

fetch_diag = fetcher.diagnostics
```
