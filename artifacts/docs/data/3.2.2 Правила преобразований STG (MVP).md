# 3.2.2 Правила преобразований STG (MVP)

Документ фиксирует реализацию подпункта `2.2` из верхнеуровневого чек-листа.

## 1) Статусы -> `is_active`

Реализация сделана через справочник `stg.ref_vacancy_status_map`.

Подход:

- вход: `status_raw` (сырой текст из источника),
- перед сопоставлением: `trim + lower`,
- выход:
  - `status_norm` (`ACTIVE | INACTIVE | UNKNOWN`),
  - `is_active` (`true | false | null`).

Базовые соответствия (MVP):

- `ACTIVE`: `active`, `активна`, `актуальна`, `опубликована`, `размещена`, `открыта`
- `INACTIVE`: `inactive`, `закрыта`, `снята`, `в архиве`, `архив`, `приостановлена`
- всё остальное -> `UNKNOWN`, `is_active = null`

## 2) Зарплата -> нормализованные поля

Исходник: `salary_raw jsonb`.

Поля STG:

- `salary_from numeric(14,2)`
- `salary_to numeric(14,2)`
- `salary_mid numeric(14,2)`
- `currency text`

Правила:

- `salary_from`: из `salary_min`, fallback: `from`, `min`.
- `salary_to`: из `salary_max`, fallback: `to`, `max`.
- Извлечение значения: первая числовая подстрока (регулярное выражение), затем приведение к `numeric(14,2)`.
- Отрицательные значения считаются невалидными и заменяются на `null`.
- Если обе границы заданы и перепутаны, применяется нормализация `from=min`, `to=max`.
- `salary_mid`:
  - если есть обе границы -> `(from + to)/2`,
  - если есть только одна -> берётся это значение,
  - иначе `null`.
- `currency`:
  - нормализуется в upper-case код,
  - `RUB/RUR/РУБ/...` -> `RUB`,
  - `USD/...` -> `USD`,
  - `EUR/...` -> `EUR`,
  - пусто/неизвестно -> `UNKNOWN`.

## 3) Регион/профессия -> минимальная нормализация

Поля STG:

- `region_norm text not null default 'UNKNOWN'`
- `profession_norm text not null default 'UNKNOWN'`

Правила:

- `region_norm`:
  - пусто -> `UNKNOWN`,
  - если строка состоит из цифр (`region_raw`) -> берём первые 2 символа как укрупнённый региональный код,
  - иначе `upper(trim(region_raw))`.
- `profession_norm`:
  - `trim(profession_raw)`,
  - пусто -> `UNKNOWN`.

## 4) Ограничения качества данных (в рамках 2.2)

На `stg.vacancies` добавлены проверки:

- `salary_from >= 0`
- `salary_to >= 0`
- `salary_from <= salary_to` (если обе границы заданы)
- `status_norm in ('ACTIVE','INACTIVE','UNKNOWN')`
