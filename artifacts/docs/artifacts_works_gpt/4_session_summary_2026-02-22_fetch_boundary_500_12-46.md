# Session Summary — 2026-02-22

## Контекст задачи

- Цель: загрузка вакансий в `raw` по регионам `66`, `77`, `78` через DAG `raw_ingest_vacancies`.
- Исходные параметры запуска:
  - `window_from=2025-01-01T00:00:00+00:00`
  - `window_to=2025-01-01T00:00:00+00:00`
  - `limit=100`
  - `max_pages=500`
  - `max_items=50000`

## Что выявили

- Изначально в fetch-логике пагинация шла с шагом `limit` (`1, 101, 201...`), что не соответствует ожидаемому page-based offset.
- После исправления шага пагинации на `1`, запросы стали идти последовательно (`1, 2, 3, ...`).
- Для указанного окна API стабильно отдаёт `HTTP 500` на глубокой странице (`offset=100`) для регионов `66/77/78`.
- По наблюдению пользователя и проверкам: в этом API конец диапазона может проявляться как серия `500`, а не `200` с пустым `vacancies`.

## Согласованный контракт поведения

- Идти последовательно по `offset=1,2,3...`.
- На `500` выполнять до `5` попыток (retry).
- Если после 5 попыток `500` и до этого были успешно загружены страницы с данными:
  - считать это штатной границей окна,
  - завершать fetch без фатального падения.
- Если `500` случается до первой успешной страницы с данными:
  - считать это критической ошибкой (failed).
- `meta.total` использовать только для диагностики/логирования, не как критерий остановки.
