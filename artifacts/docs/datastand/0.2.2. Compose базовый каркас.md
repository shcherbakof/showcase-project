## Что означает этот пункт и зачем он нужен (с учётом инфра-спека)

Тебе нужен **каркас `compose.yaml`, который задаёт правила для всего стека**: одинаковые имена, один способ конфигурирования, предсказуемая сеть/тома и обязательная готовность Postgres через healthcheck. Это критично для “Docker-only, кросс-ОС, воспроизводимо” и для будущего one-shot `db-init`, который должен стартовать **только когда Postgres реально жив**.

Подпункты:

1. **profiles и общие элементы**

- Все сервисы помечаются профилями (`db`, `db-init`, `airflow`, `superset`) → атомарный запуск модулей и меньше хаоса.

2. **одна bridge-сеть с фикс-именем**

- Один network на стек, имя фиксируется через `${COMPOSE_PROJECT_NAME}_net`.
- Запрещаем “зоопарк сетей”, иначе потом ловишь неотлаживаемые сетевые приколы (и да, это будет боль).

3. **named volumes вместо bind mount по умолчанию**

- Named volumes стабильнее на macOS/Windows/Linux (особенно Docker Desktop), меньше проблем с правами/производительностью/путями.
- Bind mount оставляем как отдельный режим, не дефолт.

4. **healthcheck для Postgres (обязателен)**

- Это “контракт готовности”: `depends_on: condition: service_healthy` для `db-init`, Airflow, Superset.
- Без этого ты будешь ловить гонки “контейнер стартанул, но Postgres ещё не принимает коннекты”.

5. **единые TZ/локаль**

- Единый `TZ=Europe/Moscow` (+3) нужен для расписаний и консистентности логов.
- `LANG/LC_ALL` фиксируют поведение утилит/клиентов (чтобы не зависеть от ОС ревьюера).

## Конкретно по шагам (что сделать)

1. Создай `.env.example` и зафиксируй:

- `COMPOSE_PROJECT_NAME=works_on_russia`
- `TZ`, `LANG`, `LC_ALL`
- переменные Postgres (tag, порт, суперюзер/пароль, locale/encoding)

2. Создай `compose.yaml`:

- (опционально) `name: ${COMPOSE_PROJECT_NAME}` чтобы проект не зависел от имени папки
- общий env-блок (YAML anchor) `x-common-env`
- `networks:` ровно одна сеть с `name: ${COMPOSE_PROJECT_NAME}_net`, driver bridge
- `volumes:` named volume(а) с `name: ${COMPOSE_PROJECT_NAME}_pgdata`
- `services.postgres` в профиле `db` с **healthcheck**

3. Прогон валидации:

- `docker compose --env-file .env.example config` (чисто проверить, что YAML валиден и интерполяция ок)

Ироничная правда жизни: если сейчас не зафиксировать сеть/тома/таймзону, потом ты будешь “фиксировать” это в 3 ночи, когда ничего не работает.

## Готовое решение

### `compose.yaml`

```yaml
name: ${COMPOSE_PROJECT_NAME}

x-common-env: &common_env
  TZ: ${TZ}
  LANG: ${LANG}
  LC_ALL: ${LC_ALL}

services:
  postgres:
    image: postgres:${POSTGRES_IMAGE_TAG}
    profiles: ["db"]
    container_name: ${COMPOSE_PROJECT_NAME}_postgres
    environment:
      <<: *common_env
      POSTGRES_USER: ${POSTGRES_SUPERUSER}
      POSTGRES_PASSWORD: ${POSTGRES_SUPERPASS}
      POSTGRES_DB: postgres
      POSTGRES_INITDB_ARGS: "--encoding=${POSTGRES_ENCODING} --locale=${POSTGRES_LOCALE}"
    ports:
      - "${POSTGRES_HOST_PORT}:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data
    networks:
      - app_net
    healthcheck:
      test:
        [
          "CMD-SHELL",
          "pg_isready -U $$POSTGRES_USER -d postgres -h 127.0.0.1 -p 5432",
        ]
      interval: 5s
      timeout: 3s
      retries: 20
      start_period: 10s

networks:
  app_net:
    name: ${COMPOSE_PROJECT_NAME}_net
    driver: bridge

volumes:
  pgdata:
    name: ${COMPOSE_PROJECT_NAME}_pgdata
```

### `.env.example`

```dotenv
# Project naming (фиксирует имена network/volumes, не зависит от имени папки)
COMPOSE_PROJECT_NAME=works_on_russia

# Timezone/locale (единые для всех контейнеров)
TZ=Europe/Moscow
LANG=C.UTF-8
LC_ALL=C.UTF-8

# Postgres image and host port
POSTGRES_IMAGE_TAG=16
POSTGRES_HOST_PORT=5432

# Postgres superuser (локально, пример)
POSTGRES_SUPERUSER=postgres
POSTGRES_SUPERPASS=postgres

# Predictable initdb defaults
POSTGRES_LOCALE=C.UTF-8
POSTGRES_ENCODING=UTF8
```

## Наводящие вопросы (ответы не блокируют, но помогут не переделывать)

1. Тебе ок `C.UTF-8` как дефолтная локаль, или принципиально нужна `ru_RU.UTF-8`?
2. Postgres tag фиксируем просто `16` (проще) или прям патч-версию `16.x.y` (жёстче воспроизводимость)?

Если хочешь — следующим шагом сразу добавлю `db-init` (one-shot) так, чтобы он зависел от `service_healthy` и был готов к порядку `000_roles.sql → 010_databases.sql → ...` без `docker-entrypoint-initdb.d`.

## Что за пункт и зачем он нужен

Это про “единый интерфейс управления стендом”, чтобы:

- запуск был **воспроизводимым** и одинаковым для тебя и ревьюера
- не плодить “магические” команды в голове (и в истории терминала)
- формализовать **2 reset-сценария** (soft/hard) и **smoke-проверку** как обязательный минимум “почти как в проде”
  Основание: требования про profiles, повторяемый db-init, soft/hard reset, Docker-only стенд.

## Конкретные шаги (что сделать)

1. В корне репо создай директорию:

- [`scripts/`](../../../scripts)

2. В [`scripts/`](../../../scripts) добавь файлы:

- `lib.sh` (общие функции)
- `up-db.sh`
- `init-db.sh`
- `reset-soft.sh`
- `reset-hard.sh`
- `up-airflow.sh`
- `up-superset.sh`
- `up-all.sh`
- `smoke.sh`

3. В корне репо добавь `Makefile`, который вызывает эти скрипты.

4. Сделай скрипты исполняемыми:

- `chmod +x scripts/*.sh`

5. Принцип (важно):

- `db-init`, `airflow-init`, `superset-init` — **one-shot** (через `docker compose run --rm ...`)
- long-running сервисы — через `docker compose up -d ...`
- `reset-soft` не трогает volume, `reset-hard` — **сносит volume**.

### scripts/lib.sh

```bash
#!/usr/bin/env bash
set -euo pipefail

dc() { docker compose "$@"; }

need_cmd() {
  command -v "$1" >/dev/null 2>&1 || { echo "Missing required command: $1" >&2; exit 127; }
}

require_compose() {
  need_cmd docker
  docker compose version >/dev/null 2>&1 || { echo "Docker Compose v2 is required: docker compose ..." >&2; exit 2; }
}

service_exists() {
  local svc="$1"
  dc config --services | grep -qx "$svc"
}

wait_healthy() {
  local svc="$1"
  local tries="${2:-60}"
  local sleep_s="${3:-2}"

  for _ in $(seq 1 "$tries"); do
    local id
    id="$(dc ps -q "$svc" || true)"
    if [[ -n "${id}" ]]; then
      local status
      status="$(docker inspect -f '{{if .State.Health}}{{.State.Health.Status}}{{else}}{{.State.Status}}{{end}}' "$id" 2>/dev/null || true)"
      if [[ "${status}" == "healthy" ]]; then
        return 0
      fi
    fi
    sleep "$sleep_s"
  done

  echo "Service '$svc' did not become healthy in time" >&2
  dc ps
  exit 3
}
```

### scripts/up-db.sh

```bash
#!/usr/bin/env bash
set -euo pipefail
source "$(dirname "$0")/lib.sh"

require_compose

if ! service_exists postgres; then
  echo "compose.yaml must define service 'postgres'" >&2
  exit 2
fi

dc --profile db up -d postgres
wait_healthy postgres 60 2
```

### scripts/init-db.sh

```bash
#!/usr/bin/env bash
set -euo pipefail
source "$(dirname "$0")/lib.sh"

require_compose

if ! service_exists db-init; then
  echo "compose.yaml must define one-shot service 'db-init' (profile db-init)" >&2
  exit 2
fi

# гарантируем, что postgres поднят
dc --profile db up -d postgres
wait_healthy postgres 60 2

# one-shot init (повторяемый)
dc --profile db-init run --rm db-init
```

### scripts/reset-soft.sh

```bash
#!/usr/bin/env bash
set -euo pipefail
source "$(dirname "$0")/lib.sh"

require_compose

# Вариант А (рекомендую): отдельный one-shot сервис db-reset-soft в profile db-init
# Вариант Б: переиспользуем db-init с MODE=reset-soft (если ты так реализуешь entrypoint)
if service_exists db-reset-soft; then
  dc --profile db-init run --rm db-reset-soft
  exit 0
fi

if service_exists db-init; then
  dc --profile db up -d postgres
  wait_healthy postgres 60 2
  dc --profile db-init run --rm -e MODE=reset-soft db-init
  exit 0
fi

echo "Need either service 'db-reset-soft' or 'db-init' that supports MODE=reset-soft" >&2
exit 2
```

```bash

set -euo pipefail
source "$(dirname "$0")/lib.sh"

require_compose

# 1) Compose config валиден
dc config >/dev/null

# 2) postgres healthy
if service_exists postgres; then
  dc --profile db up -d postgres
  wait_healthy postgres 60 2
fi

# 3) Проверка, что порты поднялись (если опубликованы в compose)
# Примечание: это smoke “по факту”, без curl-зависимостей на схемы/таблицы.
need_cmd docker

echo "Containers:"
dc ps

echo "OK: smoke passed (basic)"
```

## Как этим пользоваться

- Поднять только Postgres: `make up-db`
- Прогнать init БД: `make init-db`
- Мягкий сброс: `make reset-soft`
- Жёсткий сброс: `make reset-hard`
- Airflow: `make up-airflow`
- Superset: `make up-superset`
- Всё: `make up-all`
- Smoke: `make smoke`

Ироничная ремарка (1/4): если у тебя нет `smoke`, то “работает у меня” — это не статус, а диагноз.
